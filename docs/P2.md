# P2 plan

P1 proved the semantic/runtime architecture and selected a Rust shared portable core. P2 validates actual product-host workflows, starting on macOS.

## P2-A — macOS Capture / OCR / Overlay vertical slice

Status: Active. Authoritative task scope is `work/current.md`.

User-visible target:

```text
user explicitly triggers capture
→ selects/uses an authorized on-screen source
→ app captures a frame locally
→ local OCR extracts text
→ translation backend processes the text
→ translated result appears in a transient overlay
```

### Stage A1 — capability and requirement evidence

- inspect current macOS SDK/toolchain and existing repository host patterns
- probe native capture choices and screen-recording permission behavior
- probe native/local OCR choices and Chinese recognition capability
- probe overlay/window choices, own-window exclusion and focus behavior
- inspect P1-F Rust C ABI integration options from a macOS Swift/AppKit/SwiftUI host
- record privacy, lifecycle and cancellation semantics before implementation

Do not preselect ScreenCaptureKit, Vision, AppKit, SwiftUI, or a third-party library merely because they are common choices. Use the first evidence-supported native/project option that satisfies the confirmed requirements.

### Stage A2 — architecture and state contract

Record an ADR for:

- capture adapter
- OCR adapter
- translation-backend adapter
- overlay adapter
- request lifecycle/state owner
- permission/error mapping
- own-overlay/self-capture cycle guard
- temporary frame/text memory ownership

Minimum P2-A flow is one-shot, explicit user-triggered capture. Continuous/background capture is a future scope unless current user requirements explicitly change.

### Stage A3 — minimal native macOS app

Implement only the surface required to prove the end-to-end use case:

- app launch
- capture trigger/source selection
- local OCR
- translation handoff
- transient overlay
- cancel/dismiss/retry
- diagnostics needed for validation

Avoid account, settings, updater, telemetry, tray/menu extras, history browser, packaging polish, or generalized UI framework abstractions unless a current acceptance criterion requires them.

### Stage A4 — direct macOS validation

Direct host evidence must cover:

- permission denied and granted paths
- real on-screen capture
- controlled OCR fixture
- supported translation fixture
- unknown/unresolved safety
- overlay lifecycle
- self-capture prevention
- cancellation/re-entry
- no default capture persistence
- offline execution
- latency baseline
- P1 regressions
