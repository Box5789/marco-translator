# P1 plan

P1 is a proof of the architecture, not a claim of general translation quality.

Current direct validation priority: **macOS**. Final target platforms: **macOS / Windows / Android / iOS**.

## P1-A — contracts and deterministic pipeline

- [x] request/result/semantic-frame types
- [x] conservative normalization
- [x] exact translation memory
- [x] deterministic semantic resolver boundary
- [x] rule-first realizer
- [x] neural realizer interface only
- [x] JSONL decision log
- [x] KG patch proposal validation boundary
- [x] external maintenance prompt
- [x] initial zh→ko gaming regression cases

## P1-B — MARCO translator pack

- [x] define translator semantic ontology
- [x] map MARCO semantic node -> frame -> target terminology
- [x] create minimal zh→ko MARCO source graph + frame map
- [x] compile and run the minimal zh→ko `.mco` pack against an upstream MARCO checkout
- [x] make `MarcoResolver` pass the same regression cases as the deterministic fixture resolver
- [x] prove unknown input returns unknown instead of a guessed translation

## P1-C — user overlay

- [x] persistent user terminology table
- [x] explicit correction -> TM write
- [x] repeated correction -> overlay proposal
- [x] session-only entity bindings
- [x] reversible routing-weight adaptation

## P1-D — knowledge maintenance

- [ ] export low-confidence and unresolved subsets separately
- [ ] include stable evidence IDs
- [ ] patch validation with evidence/base-version/conflict checks
- [ ] patch dry-run preview without active KG mutation
- [ ] corpus replay before/after report
- [ ] user approval transaction
- [ ] atomic KG version activation
- [ ] versioned rollback
- [ ] offline/security/failure validation
- [ ] macOS direct file/persistence validation where environment permits

Detailed active scope: `work/current.md`.

## P1-E — tiny realizer benchmark

Compare at least:

- deterministic rules only
- a sub-1B off-the-shelf local model used strictly as a realizer
- a 100–300M distilled/fine-tuned candidate if data justifies it

Metrics:

- semantic preservation against frame
- terminology compliance
- fluency
- latency
- peak RAM
- model size
- neural invocation rate

First direct benchmark platform: macOS. Do not fix a model/runtime before comparable measurement.

## P1-F — cross-platform runtime gate

Verify that stable core contracts can be implemented for macOS, Windows, Android and iOS without depending on Python-only or platform-UI internals.

Required evidence includes:

- portable request/result/frame/persistence schemas
- fixture parity across runtime implementations
- replaceable semantic-engine/model-runtime boundaries
- platform-specific capture/OCR/overlay isolation
- persistence/version compatibility
- resource/permission constraints measured per platform

The shared native core language is selected only after the evidence and ADR required by `docs/PLATFORM_STRATEGY.md`.
