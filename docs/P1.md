# P1 plan

P1 is a proof of the architecture, not a claim of general translation quality.

Current direct validation priority: **macOS**. Final target platforms: **macOS / Windows / Android / iOS**.

## P1-A — contracts and deterministic pipeline

- [x] request/result/semantic-frame types
- [x] conservative normalization
- [x] exact translation memory
- [x] deterministic semantic resolver boundary
- [x] rule-first realizer
- [x] neural realizer interface only
- [x] JSONL decision log
- [x] KG patch proposal validation boundary
- [x] external maintenance prompt
- [x] initial zh→ko gaming regression cases

## P1-B — MARCO translator pack

- [x] define translator semantic ontology
- [x] map MARCO semantic node -> frame -> target terminology
- [x] create minimal zh→ko MARCO source graph + frame map
- [x] compile and run the minimal zh→ko `.mco` pack against an upstream MARCO checkout
- [x] make `MarcoResolver` pass the same regression cases as the deterministic fixture resolver
- [x] prove unknown input returns unknown instead of a guessed translation

## P1-C — user overlay

- [x] persistent user terminology table
- [x] explicit correction -> TM write
- [x] repeated correction -> overlay proposal
- [x] session-only entity bindings
- [x] reversible routing-weight adaptation

## P1-D — knowledge maintenance

- [x] export low-confidence and unresolved subsets separately
- [x] include stable evidence IDs
- [x] `kg-patch-v2` validation with evidence/base-version/target/expected-state/conflict checks for all seven operations
- [x] patch dry-run preview without active KG mutation
- [x] actual MARCO rebuild and before/after corpus replay report with regression gate
- [x] explicit approval bound to the candidate version ID

- [x] offline/security/failure validation
- [x] macOS direct file/persistence validation

Detailed active scope: `work/current.md`.

## P1-E — tiny realizer benchmark

Compare at least:

- deterministic rules only
- a sub-1B off-the-shelf local model used strictly as a realizer
- a 100–300M distilled/fine-tuned candidate if data justifies it

Metrics:

- semantic preservation against frame
- terminology compliance
- fluency
- latency
- peak RAM
- model size
- neural invocation rate

First direct benchmark platform: macOS. Do not fix a model/runtime before comparable measurement.

P1-E result (2026-09-25): workload `benchmarks/p1-e/workload.v1.json`; two sandboxed macOS reports are stored in `benchmarks/p1-e/results/`.

- [x] freeze and hash the actual MARCO-derived workload and benchmark prompts
- [x] measure the rule-only baseline and a sub-1B local candidate on the same frames
- [x] record semantic, exact terminology, and fluency metrics independently
- [x] record cold/warm latency, sampled peak RSS, and model artifact size
- [x] verify offline local inference and actual pipeline neural invocation rate
- [x] retain P1-A–P1-D regressions and actual upstream MARCO integration
- [x] assess the 100–300M training candidate; not justified with the current data and zero neural invocations
- [x] hold the tested Qwen3 candidate because semantic hard checks passed 0/5; leave product runtime and P1-F architecture undecided

Verify that stable core contracts can be implemented for macOS, Windows, Android and iOS without depending on Python-only or platform-UI internals.

Required evidence includes:

- [x] inventory Python-only coupling and freeze portable request/result/frame/term/error contracts

- [x] compare runtime architecture candidates with source/capability evidence and record the selected ADR
- [x] implement the smallest non-Python/product-runtime vertical slice needed to prove the selected architecture
- [x] prove replaceable semantic-resolver and neural-realizer boundaries without weakening unresolved safety
- [x] prove runtime persistence/interchange semantic parity
- [x] run direct macOS conformance
- [x] run Windows native conformance
- [x] run Android emulator/runtime smoke
- [x] run iOS simulator/runtime smoke
- [x] verify offline/Python-runtime-independent execution for the portable slice
