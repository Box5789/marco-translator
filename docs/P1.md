# P1 plan

P1 is a proof of the architecture, not a claim of general translation quality.

## P1-A — contracts and deterministic pipeline

- [x] request/result/semantic-frame types
- [x] conservative normalization
- [x] exact translation memory
- [x] deterministic semantic resolver boundary
- [x] rule-first realizer
- [x] neural realizer interface only
- [x] JSONL decision log
- [x] KG patch proposal validation boundary
- [x] external maintenance prompt
- [x] initial zh→ko gaming regression cases

## P1-B — MARCO translator pack

- [ ] define translator semantic ontology
- [ ] map expression -> sense -> concept -> target terminology
- [ ] create a minimal zh→ko `.mco` pack
- [ ] make `MarcoResolver` pass the same regression cases as the deterministic fixture resolver
- [ ] prove unknown input returns unknown instead of a guessed translation

## P1-C — user overlay

- [ ] persistent user terminology table
- [ ] explicit correction -> TM write
- [ ] repeated correction -> overlay proposal
- [ ] session-only entity bindings
- [ ] reversible routing-weight adaptation

## P1-D — maintenance package

- [ ] export low-confidence and unresolved subsets separately
- [ ] include stable evidence IDs
- [ ] patch dry-run preview
- [ ] corpus replay before/after report
- [ ] user approval transaction
- [ ] versioned rollback

## P1-E — tiny realizer benchmark

Compare at least:

- deterministic rules only
- a sub-1B off-the-shelf local model used strictly as a realizer
- a 100–300M distilled/fine-tuned candidate if data justifies it

Metrics:

- semantic preservation against frame
- terminology compliance
- fluency
- latency
- peak RAM
- model size
- neural invocation rate

## P1-F — mobile feasibility gate

The design passes the gate only if the core can be ported without depending on Python-only MARCO internals. The app/runtime contract must remain stable while the semantic engine implementation is swapped.
